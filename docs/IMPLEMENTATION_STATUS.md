# Project G-One 구현 현황

## 문서 목적

이 문서는 기능 작업 사이에 제품 목적과 현재 구현 상태를 잃지 않기 위한 작업 기준이다.
기능을 추가하거나 사용자 흐름을 변경할 때 코드와 함께 이 문서를 갱신한다.

## 변하지 않는 제품 목표

- 사용자는 **G-One 프로그램 하나만 설치하고 로그인**한다.
- 로그인 성공 여부는 VPN, 파일 서버 또는 부가 기능의 일시적 실패와 분리한다.
- 로그인 후 VPN과 허가된 파일 공유 연결은 별도 프로그램 조작 없이 자동 수행한다.
- 로그아웃과 프로그램 종료 시 세션에서 만든 VPN 및 파일 공유 연결을 정리한다.
- VPN, 파일 서비스와 원격 지원은 하나의 클라이언트 화면에서 상태와 오류를 확인한다.

## 현재 구현 상태

| 영역 | 상태 | 현재 동작 |
| --- | --- | --- |
| 사용자 인증 | 구현 | 계정과 암호로 로그인하며 토큰은 메모리에만 보관한다. |
| 장치 등록 | 구현 | 로그인한 Windows 장치를 자동 등록하고 정책을 15초마다 확인한다. |
| VPN 서버 | 구현 | WireGuard 네트워크와 피어 구성을 생성하고 서버 설정을 반영한다. |
| Windows VPN | 구현/검증 필요 | 단일 EXE에 공식 런타임을 포함하고 로그인 후 터널 연결을 시도한다. 실패해도 로그인 세션은 유지하며 15초마다 재시도한다. |
| 파일 서버 연결 | 미구현 | 정책 모델, SMB 자격 증명 브로커, 자동 연결 및 해제 기능이 필요하다. |
| 원격 지원 | 부분 구현 | 서버의 요청·동의 API만 있으며 Windows 화면 제어 데이터면은 미구현이다. |

## 이번 변경에서 지킨 회귀 기준

1. 올바른 계정이면 VPN 설정 누락, 서버 키 누락, UAC 취소 또는 터널 설치 실패가 발생해도
   로그인 화면으로 되돌리지 않는다.
2. 로그인 직후 대시보드를 표시하고 VPN 상태를 별도로 보여준다.
3. VPN 연결에 실패하면 로그인 세션을 유지한 채 정책 주기에 맞춰 자동 재시도한다.
4. 실제 인증 실패만 로그인 실패로 표시한다.

## 다음 우선순위

1. Windows CI에서 내장 WireGuard 런타임 설치, 로그인, 터널 생성과 로그아웃 정리를 검증한다.
2. 파일 공유 정책 API와 단기 SMB 자격 증명 계약을 정의한다.
3. Windows 클라이언트에 허가된 SMB 공유 자동 연결, 상태 표시 및 로그아웃 해제를 구현한다.
4. VPN과 SMB를 일반 사용자 UI와 권한이 분리된 Windows 서비스로 이동한다.

## 완료 전 확인 목록

- 인증 성공과 부가 기능 연결 성공을 같은 `try/catch` 실패 경로로 묶지 않았는가?
- 사용자가 G-One 이외의 프로그램을 직접 내려받거나 조작해야 하지는 않는가?
- 기능 실패가 다른 정상 기능과 로그아웃 정리를 방해하지 않는가?
- UI에 로그인, VPN, 파일 공유 상태가 서로 구분되어 표시되는가?
- 테스트, 알려진 제한과 다음 작업을 이 문서에 반영했는가?
