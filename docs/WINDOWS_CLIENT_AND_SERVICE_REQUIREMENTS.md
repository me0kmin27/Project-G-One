# Windows 클라이언트 및 서비스 요구사항

## 1. 목적과 범위

이 문서는 Windows 전용 배포 프로그램을 중심으로 한 사용자 경험, 인증, VPN·파일 서버,
원격 지원, 티켓, 멀티테넌시와 라이선스 요구사항을 정의한다. 구현 시 편의성을 높이되
로그인 생략이나 Windows 자격 증명 저장을 편의 기능으로 제공하지 않는 것을 최우선
보안 제약으로 삼는다.

- 대상 클라이언트: 지원 수명 주기 내의 Windows 데스크톱
- 제공 형태: 중앙 서비스형 멀티테넌시 및 고객사 자체 호스팅
- 핵심 여정: **프로그램 실행 → 매번 로그인 → VPN·파일 공유 자동 구성 → 통합 업무 수행**
- 상태: 제품 요구사항 기준선. 구체 프로토콜과 구현 제품은 위협 모델 및 기술 검증 후 ADR로 확정한다.

## 2. 사용자 경험과 Windows 에이전트

설치 후 사용자가 수행하는 필수 작업은 프로그램 실행과 대화형 로그인뿐이어야 한다.
로그인 성공 후 에이전트는 서버에서 해당 사용자·장치·조직 정책을 받아 다음 작업을
사용자 개입 없이 수행한다.

1. 장치 상태와 정책 버전을 확인한다.
2. 장치별 WireGuard 키를 안전하게 생성·등록하고 허용된 터널을 구성한다.
3. 접근 가능한 파일 공유를 조회하고 SMB 연결을 구성한다.
4. 원격 지원 요청, 티켓 생성·조회 및 파일 서버 진입점을 프로그램 안에 표시한다.
5. 로그아웃·세션 만료·권한 회수 시 터널, 공유 연결과 임시 자격 증명을 정리한다.

설치 프로그램은 관리자 권한이 필요한 시스템 서비스와 일반 사용자 UI를 분리한다.
권한이 낮은 UI가 임의의 WireGuard·방화벽·SMB 명령을 서비스에 전달할 수 없도록 서명된
정책과 제한된 IPC 계약을 사용한다. 자동 구성은 멱등적이어야 하며 부분 실패 시 사용자에게
실패 항목과 재시도 상태를 보여주고, 이전의 안전한 구성으로 되돌릴 수 있어야 한다.

### 통합 화면의 최소 기능

- 현재 VPN 및 파일 공유 연결 상태와 정책 갱신 시각
- 권한이 부여된 파일 서버·공유 열기와 연결 복구
- 목적과 첨부 파일을 포함한 지원 티켓 생성, 진행 상태 및 답변 조회
- 요청자·목적·권한을 표시하는 원격 지원 요청의 수락·거절·종료
- 세션 만료 경고, 명시적 로그아웃과 로컬 연결 정리 결과

## 3. 인증과 세션 보안

### 절대 제약

- 자동 로그인, 로그인 상태 유지, 장기 refresh token을 이용한 무인 재인증을 제공하지 않는다.
- Windows 자격 증명 관리자, 브라우저 비밀번호 저장소, 레지스트리, 구성 파일 또는 앱 DB에
  사용자 비밀번호나 재사용 가능한 로그인 자격 증명을 저장하지 않는다.
- WebView 또는 시스템 브라우저의 SSO 쿠키만으로 다음 앱 실행의 로그인을 통과시키지 않는다.
- Windows 시작, 사용자 로그인, 잠금 후 업무 재개 또는 앱 재실행 시 유효한 대화형 앱 세션이
  없다면 로그인을 강제한다. 장치 키는 사용자 로그인 자격 증명을 대체할 수 없다.
- SMB에 `cmdkey`, 영구 드라이브 매핑 등 자격 증명을 기억시키는 방식을 사용하지 않는다.

앱 세션과 백엔드 토큰은 짧은 수명으로 발급하고 유휴 시간 제한과 절대 수명 제한을 모두 둔다.
정확한 기본값은 위협 모델에서 확정하되 정책으로 더 짧게 설정할 수 있어야 한다. 세션 연장은
사용자 활동만으로 무기한 이뤄지지 않으며, 절대 수명 도달 및 고위험 작업 시 재인증한다.
Windows 잠금·로그오프, 절전 복귀와 네트워크 전환 이벤트를 감지해 세션 재검증 또는 종료를
수행한다.

메모리에만 존재하는 액세스 토큰과 SMB 임시 자격 증명도 로그·크래시 덤프·진단 번들에서
제외하고 만료나 로그아웃 시 제거한다. 장치 WireGuard 개인 키처럼 지속성이 필요한 장치
비밀은 내보낼 수 없도록 OS 보호 저장소에 장치 단위로 보호하되, 이것을 사용자 인증 성공의
근거로 사용하지 않는다.

## 4. VPN 중계와 네트워크 권한

WireGuard는 장치와 VPN 게이트웨이 사이의 1:1 피어 관계로 구성한다. 장치가 파일 서버에
직접 피어링하는 구조가 아니라 게이트웨이가 트래픽을 중계하며, 게이트웨이의 방화벽과 정책
엔진이 실제 접근 경계가 된다.

- 조직(tenant), 사용자, 그룹, 장치와 대상 서비스 단위로 네트워크 허용 정책을 계산한다.
- 사용자 피어 간 통신과 고객 조직 간 통신은 기본 차단한다.
- 파일 서버의 주소·포트 접근은 명시적 `NetworkGrant`가 있을 때만 허용한다.
- `AllowedIPs`는 라우팅 구성 요소일 뿐 유일한 인가 수단으로 간주하지 않는다.
- 로그인 성공 후 최소 범위의 구성을 배포하고, 로그아웃·세션 만료·계정 비활성화 시 정해진
  시간 안에 방화벽 허용과 활성 피어 세션을 회수한다.
- 모든 정책 계산과 적용 결과에는 조직 ID, 사용자, 장치, 정책 버전과 상관관계 ID를 기록한다.

제어면 장애 시 보안 정책이 열린 상태로 바뀌어서는 안 된다. 세션 만료 후 게이트웨이에
도달하지 못한 클라이언트의 로컬 구성 정리뿐 아니라, 게이트웨이 측 임대(lease) 만료로도
접근을 닫는 이중 회수 장치를 둔다.

## 5. 파일 서버 접근과 파일 수준 권한

VPN 연결 허용과 파일 열람 권한은 서로 다른 계층이다. 네트워크 정책이 파일 서버까지의
경로를 허용해도, 파일 서버는 사용자 또는 그룹에 부여된 별도 `FileGrant`와 자체 ACL로
공유·폴더·파일의 목록 조회, 읽기, 쓰기, 삭제 권한을 결정해야 한다.

로그인 후 클라이언트는 허가된 SMB 공유만 자동 연결한다. SMB 자격 증명은 SSO 토큰을 직접
재사용하지 않고 짧은 수명의 브로커 자격 증명 또는 고객 디렉터리 연동으로 발급한다. 연결은
비영구 방식이어야 하며 앱 세션 종료 시 해제한다. 서버 측 ACL이 최종 권한 기준이어야 하고,
UI에서 항목을 숨기는 것을 보안 통제로 간주하지 않는다.

자체 호스팅 배포에서는 SMB 자동 연결을 기본 제공 기능으로 둔다. 중앙 서비스형 배포의 파일
접근은 고객 조직별 네트워크·디렉터리·파일 서버 어댑터로 격리하며, 서비스 운영자가 파일
내용에 접근하지 않아도 되도록 데이터 경로를 설계한다.

## 6. 원격 지원과 티켓

지원 담당자는 티켓에서 대상 장치에 원격 지원을 요청할 수 있다. 피지원자는 요청자, 소속,
목적, 만료 시각과 요청된 권한을 확인하고 명시적으로 수락하거나 거절한다. 수락된 세션은
화면 보기, 키보드·마우스 제어, 클립보드, 파일 전송, 관리자 파일 서버의 허가된 자료 전달을
각각 독립 권한으로 제한한다.

- 화면 보기와 직접 입력 제어를 지원하며 세션 중 양쪽에 지속적인 표시를 제공한다.
- 어느 쪽이든 즉시 세션을 종료할 수 있고 동의 범위를 세션 도중 확대할 때 다시 동의받는다.
- 지원 담당자의 파일 서버 연결 권한을 원격 PC에 그대로 위임하지 않는다.
- 관리자 자료 전달은 서버 측 권한 확인 후 세션 전용 스트림 또는 단기 다운로드로 제공하며,
  경로 노출, 임의 파일 탐색과 자격 증명 전달을 금지한다.
- 사용자 PC에서 관리자로의 업로드, 관리자에서 사용자 PC로의 다운로드, 해시, 크기, 결과를
  감사하되 기본적으로 파일 내용이나 민감한 전체 경로를 로그에 남기지 않는다.
- 요청, 동의, 제어 시작·종료, 파일 전송과 실패를 티켓 및 변경 불가 감사 이벤트에 연결한다.

티켓은 조직 경계를 벗어나 조회되지 않아야 하며 생성자, 담당자, 상태, 우선순위, 설명,
첨부 메타데이터와 감사 이력을 갖는다. 첨부 파일은 악성코드 검사, 크기·형식 제한, 암호화
저장과 보존 정책을 적용한다.

## 7. 멀티테넌시와 자체 호스팅

모든 서비스형 데이터 모델과 요청 컨텍스트는 필수 `tenant_id`를 포함한다. 사용자 ID가
같더라도 조직이 다르면 별도 주체로 취급하고, DB 행 수준 정책 또는 동등한 강제 장치,
조직별 객체 저장소 경로, 캐시 키, 작업 큐, 감사 조회와 암호화 키 범위를 적용한다.
VPN 주소 대역과 방화벽 체인도 조직별로 충돌 및 우회가 없도록 격리한다.

고객사 관리자는 자기 조직의 사용자·그룹, 파일 권한, 지원 담당자, 장치, 정책과 라이선스
범위만 관리할 수 있다. 플랫폼 운영자 권한도 고객 데이터에 대한 묵시적 접근을 주지 않으며,
필요한 지원 접근은 시간 제한, 사유 입력, 고객 승인과 감사를 거친다.

자체 호스팅은 동일한 보안 모델을 유지하되 단일 조직 모드를 지원한다. 구성 내보내기·백업,
키 회전, 업데이트, 오프라인 또는 제한망 라이선스 검증과 장애 시 복구 절차를 제공해야 한다.

## 8. 구독 및 고객 관리 토큰

서비스형 기능은 구독으로 제공하고, 자체 호스팅의 SMB 자동 연결 기능은 구독 검증 없이
사용할 수 있어야 한다. 그 외 자체 호스팅 기능의 권한 범위는 서명된 라이선스 토큰으로
검증한다.

고객 조직이 별도로 관리하는 경우 플랫폼은 고객 관리자용 등록·관리 토큰을 발행한다.
토큰은 월별, 분기별 또는 연별 기간을 선택할 수 있으며 다음 클레임을 최소로 포함한다.

- 고유 토큰 ID, 발급자, 고객 조직 ID, 대상 배포 ID
- 시작 시각, 만료 시각, 발급 주기(월·분기·연)
- 허용 기능, 사용자·장치 한도와 제품 등급
- 키 ID와 서명 알고리즘 버전

토큰은 위변조를 막기 위해 비대칭 서명하고 서버에는 원문 대신 식별자와 상태를 저장한다.
발급, 갱신, 폐기와 검증 실패를 감사하며 조직·배포 간 재사용을 차단한다. 관리 토큰은 사용자
로그인 토큰이 아니며 대화형 로그인이나 개별 사용자의 권한 검사를 생략할 수 없다. 만료 시
새 관리 작업과 유료 기능 시작은 차단하되, 데이터 내보내기·로그인·SMB 자동 연결 등 계약과
복구에 필요한 최소 기능의 유예 정책을 명확히 정의한다.

## 9. 수용 기준

1. 새 Windows PC에서 한 번 설치한 뒤 사용자는 앱 로그인 외 수동 VPN·SMB 설정 없이 허가된
   공유와 프로그램 내 기능을 사용할 수 있다.
2. 앱 종료 후 재실행, Windows 로그오프 후 로그인, 장시간 유휴 및 절대 세션 만료 뒤에는
   저장된 자격 증명으로 우회하지 못하고 대화형 로그인이 다시 요구된다.
3. Windows 자격 증명 관리자와 영구 SMB 매핑에 사용자 또는 SMB 로그인 비밀이 남지 않는다.
4. 같은 VPN 게이트웨이를 사용하는 서로 다른 조직과 권한 없는 그룹 사이의 패킷이 차단된다.
5. 파일 서버 네트워크 접근 권한이 있어도 `FileGrant`와 서버 ACL이 없는 파일은 열람·추측
   경로 접근·검색 결과에서 모두 거부된다.
6. 지원 세션은 수락한 권한으로만 화면 제어와 파일 전송이 가능하고 거절·만료·종료 후에는
   재사용할 수 없다.
7. 고객 관리 토큰은 선택한 월·분기·연 기간과 조직·배포 범위 밖에서 검증에 실패하며,
   폐기 결과가 허용된 운영 시간 안에 반영된다.
8. 위 동작의 성공·거부·회수 결과가 tenant 범위의 감사 이벤트로 재현 가능하다.

## 10. 구현 전 확정할 항목

- 지원할 Windows 버전·에디션과 잠금/절전 시 세션 종료 정책
- 앱 유휴 수명, 절대 수명, 게이트웨이 임대 수명과 권한 회수 목표 시간
- SMB 임시 자격 증명 브로커 및 Windows 서비스 계정 모델
- 원격 화면 제어 프로토콜, UAC 보안 데스크톱 처리, 종단 간 암호화와 파일 검사 방식
- 자체 호스팅 무료/구독 기능표, 유예 기간, 오프라인 토큰 갱신 및 폐기 모델
- 조직별 규모, VPN 주소 설계, 데이터 보존 지역과 감사 로그 보존 기간
