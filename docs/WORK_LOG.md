# Project G-One 작업 기록

## 기록 규칙

모든 변경은 날짜, 요청, 승인 범위, 수행 내용, 변경 파일, 검증 결과, 미결정 사항과 다음
승인 지점을 기록한다. 기존 항목을 지우거나 결과만 바꾸지 않고, 정정이 필요하면 새 항목을
추가하여 이전 판단과 변경 이유를 추적 가능하게 한다. 비밀번호, 토큰, 개인 키와 개인정보는
기록하지 않는다.

## 2026-09-11 — 재작업 0단계 기준 수립

### 요청 및 승인

- 기존 Git 이력은 보존한다.
- 기존 소스를 즉시 삭제하지 않고 현황 분석, 요구사항, 보안 구조와 디렉터리 설계를 먼저
  제안한다.
- 단일 Debian 서버를 대상으로 하며 컨테이너 운영 복잡도를 사용자에게 노출하지 않는다.
- 서버 기능은 웹, VPN·파일 서버 연결 제어 및 원격 지원이다.
- 외부 Windows 사용자가 VPN으로 접속한 뒤 내부망의 별도 파일 서버에 접근하는 것을
  통제한다.
- Active Directory 등 외부 신원 연동을 고려한다.

### 수행

- Git 추적 파일과 최근 이력을 확인했다.
- 기존 서버, Windows 클라이언트, Compose, CI, API 경로 및 설계 문서를 정적 검토했다.
- 기존 구현을 삭제하거나 런타임 구성을 변경하지 않았다.
- 재작업 요구사항 기준선, 현황 감사와 목표 아키텍처를 작성했다.
- 서버와 Windows 클라이언트의 책임 및 제안 디렉터리를 명확히 분리했다.

### 핵심 제안

- FastAPI 기반 모듈형 모놀리스와 PostgreSQL 제어면
- React 기반 관리자/사용자 웹 진입점 분리
- Docker Compose의 비특권 애플리케이션과 systemd 특권 네트워크 적용기 분리
- Debian 호스트 WireGuard와 nftables의 장치별 목적지 정책
- .NET WPF 사용자 UI와 Windows Service의 특권 경계 분리
- Caddy와 단일 `g-one` 관리 명령을 통한 도메인/TLS 및 운영 단순화

### 검증 및 제한

- 문서 링크 및 공백 오류 검사를 수행한다.
- 현재 단계는 설계 문서만 변경하므로 애플리케이션 런타임 동작은 변경하지 않는다.
- 공식 기술 버전의 온라인 재검증을 시도했으나 웹 검색 도구 인증 제한으로 수행하지
  못했다. 구현 착수 시 공식 지원 수명을 다시 확인하고 ADR에 고정해야 한다.

### 다음 승인 지점

- `REWORK_BASELINE.md`와 `TARGET_ARCHITECTURE.md` 승인
- Windows/네트워크/파일 서버/보존 기간의 열린 질문 답변
- 기존 소스 교체 및 새 디렉터리 골격 구현 착수 승인

## 2026-09-11 — Windows 프로그램 웹 통합 배포 요구사항 반영

### 사용자 정정

- Windows 프로그램을 별도의 사용자 배포물로 운영하지 않는다.
- 관리자 또는 로그인한 사용자가 G-One 웹서버에서 직접 내려받을 수 있어야 한다.
- 관리자는 다운로드 대상 프로그램이 연결할 VPN과 파일 서버를 웹에서 지정한다.

### 반영

- 관리자 배포 프로필에 VPN 정책, 내부망 CIDR, 파일 서버·공유, 사용자·그룹과 원격 지원
  범위를 연결하도록 기준선을 보완했다.
- 범용 서명 설치 파일과 사용자별 배포 프로필을 인증된 웹 다운로드로 제공하도록 했다.
- 패키지에 VPN 개인 키나 SMB 암호를 넣지 않고, 짧게 만료되는 일회 등록 코드와 설치 후
  장치 키 생성을 사용하는 등록 흐름을 명시했다.
- 패키지 게시·다운로드·장치 등록을 감사 대상으로 추가했다.

### 보안상 해석

“설정하여 다운받기”는 사용자별 EXE에 영구 비밀을 삽입한다는 의미가 아니라 서버에 저장된
revision 기반 정책을 대상 사용자/그룹에 할당한다는 의미로 구현한다. 따라서 관리자가
정책을 변경·회수할 수 있고, 유출된 설치 파일만으로 VPN이나 파일 서버에 접근할 수 없다.

### 다음 승인 지점

- 보완된 웹 다운로드 및 장치 등록 흐름 승인
- 기존 소스 교체와 새 골격 구현 착수 승인

## 2026-09-11 — 웹 통합 클라이언트 배포 구현 착수

### 승인

- 사용자가 현재까지 확정한 내용을 기반으로 구현 시작을 승인했다.

### 구현

- 내부 SMB 파일 서버와 공유 목록을 관리하는 tenant 범위 데이터 모델과 API를 추가했다.
- 관리자가 VPN, 허용 경로, 파일 서버와 대상 사용자를 묶는 배포 프로필을 게시할 수 있게
  했다.
- 할당된 사용자 또는 관리자가 인증 후 Windows 실행 파일과 `deployment.json`을 ZIP으로
  내려받는 API를 구현했다.
- 다운로드마다 10분 후 만료되는 1회 등록 코드를 생성하고 해시만 데이터베이스에 저장한다.
- 다운로드 번들에는 VPN 개인 키, SMB 암호 또는 사용자 세션 토큰을 포함하지 않는다.
- 웹 관리 콘솔에 파일 서버 등록, 배포 프로필 생성 및 다운로드 화면을 추가했다.
- 패키지 생성·다운로드와 대리 다운로드 대상을 감사 이벤트로 기록한다.

### 검증 기준

- 다른 tenant의 파일 서버·VPN·사용자를 배포 프로필에 연결할 수 없어야 한다.
- 할당되지 않은 사용자는 프로필을 조회하거나 다운로드할 수 없어야 한다.
- 다운로드 응답은 `no-store`이며 실행 파일과 대상별 manifest를 포함해야 한다.
- 클라이언트 실행 파일이 서버에 게시되지 않았으면 빈 파일 대신 명확한 503을 반환한다.
