# Project G-One 재작업 요구사항 기준선

## 1. 문서 상태

- 상태: **검토 요청**
- 기준일: 2026-09-11
- 범위: 재작업 0단계(현황 분석, 요구사항, 보안·배포 구조, 디렉터리 설계)
- 구현 승인: **아직 받지 않음**

이 문서는 재작업의 최우선 기준이다. 기존 문서 또는 구현과 충돌하면 이 문서를 먼저
검토하며, 충돌을 임의로 해소하지 않고 작업 기록에 남긴 뒤 승인을 받는다. 현재 Git
이력은 보존하며, 기존 소스의 삭제·교체는 다음 단계의 별도 승인 전까지 수행하지 않는다.

## 2. 확정된 목표

Project G-One은 외부 Windows 장치가 먼저 중앙 서버의 WireGuard VPN에 연결한 뒤, 중앙
서버 자체 서비스와 내부망에 있는 **별도 파일 서버**에 접근하도록 인증·인가·감사하는
단일 Debian 서버용 접근 제어 플랫폼이다.

중앙 서버가 제공하는 제품 기능은 다음과 같다.

1. 관리자 및 사용자용 웹 서비스
2. WireGuard VPN 등록, 정책 배포, 연결 상태 및 접근 회수
3. VPN을 경유한 별도 SMB 파일 서버 연결 권한의 배포와 회수
4. 티켓 및 사용자 동의 기반 원격 지원 조정
5. 사용자, 장치, 역할, 정책과 감사 기록 관리
6. 관리자가 지정한 VPN·파일 서버 정책이 연결된 Windows 설치 패키지의 웹 다운로드

중앙 서버는 파일 내용을 저장하거나 파일 트래픽을 웹 애플리케이션을 통해 프록시하지
않는다. 파일 데이터는 `Windows 클라이언트 → WireGuard → 내부망 파일 서버` 경로로
이동하고, G-One은 이 경로에 필요한 신원·네트워크·서비스 권한을 제어한다.

## 3. 배포 제약

- 단일 Debian 서버에서 운영한다.
- 컨테이너 사용은 허용하지만 설치·업데이트·백업·복구·장애 진단을 단일 관리 명령으로
  제공하여 운영자가 Compose 내부 구조를 일상적으로 다루지 않게 한다.
- 초기 설치는 IP와 로컬 인증서로도 완료할 수 있어야 한다.
- 공개 도메인과 공인 TLS 인증서는 설치 후 설정 마법사에서 자연스럽게 추가·교체할 수
  있어야 하며 애플리케이션 재설치를 요구하지 않는다.
- 초기에는 내장 계정으로 동작하되 OIDC와 Active Directory/LDAP 연동을 위한 신원
  공급자 경계를 유지한다.
- VPN 서버와 웹 제어면은 같은 물리 서버에 배치할 수 있지만 권한과 프로세스 경계는
  분리한다.

## 4. 서버와 Windows 클라이언트의 책임

### 4.1 서버

서버는 다음 책임만 가진다.

- 사용자·장치 인증과 세션 발급
- 관리자/사용자 API와 웹 UI의 권한 분리
- VPN 피어 수명 주기와 방화벽 정책 계산
- 별도 파일 서버, 공유 및 접근 정책 카탈로그 관리
- 클라이언트별 허용 경로와 공유 연결 정보 배포
- 원격 지원 티켓, 동의, 만료 및 세션 조정
- 모든 고위험 동작의 감사 이벤트 기록
- 구성 검증, 원자적 적용, 상태 점검과 롤백

웹 프로세스에 `NET_ADMIN` 또는 호스트 루트 권한을 직접 주지 않는다. 네트워크 변경은
작고 제한된 명령 계약을 가진 별도 특권 서비스가 수행한다.

### 4.2 Windows 클라이언트

Windows 프로그램은 서버와 무관하게 별도 배포하거나 사용자가 외부 사이트에서 구하는
제품으로 운영하지 않는다. 서버가 Windows 실행 파일의 승인된 버전을 보관하고, 관리자와
로그인한 사용자는 권한이 있을 때 G-One 웹에서 직접 내려받는다. 내부 구현은 최소 권한을
위해 사용자 UI와 Windows 서비스를 분리한다.

- **사용자 UI:** 로그인, VPN/파일 공유 상태, 티켓, 원격 지원 동의와 오류 설명
- **Windows 서비스:** 장치 키 보호, WireGuard 터널, 라우트, SMB 연결, 정책 갱신,
  세션 정리와 원격 지원 런타임

UI 프로세스는 관리자 권한을 상시 보유하지 않는다. Windows 서비스는 서버가 서명한
정책이라도 장치·사용자·만료·재생 방지 정보를 검증한 뒤 허용 목록에 있는 작업만
수행한다. 사용자 암호, 액세스 토큰, WireGuard 개인 키를 로그에 남기지 않는다.

### 4.3 웹 기반 Windows 패키지 배포

관리자는 웹에서 **클라이언트 배포 프로필**을 만들며 다음 항목을 선택한다.

- 연결할 G-One 서버와 WireGuard VPN 정책
- VPN 연결 후 접근을 허용할 내부망 CIDR
- 연결할 파일 서버와 공유 목록
- 파일 서버별 인증 방식과 자동 연결 여부
- 원격 지원 허용 기능과 업데이트 채널
- 이 프로필을 내려받을 수 있는 사용자 또는 그룹

관리자 또는 허가된 로그인 사용자가 다운로드를 요청하면 서버는 승인된 Windows 설치
파일과 해당 배포 프로필을 하나의 다운로드 결과로 제공한다. 관리자는 특정 사용자에게
할당한 결과를 대신 내려받을 수도 있지만, 그 사실과 대상 사용자를 감사 기록에 남긴다.

다운로드 파일에는 사용자 암호, SMB 암호, WireGuard 개인 키 또는 장기 API 토큰을 넣지
않는다. 대신 서버 주소, 프로필 식별자와 짧은 만료 시간·1회 사용·대상 사용자 제한을 가진
등록 코드를 전달한다. 설치 후 프로그램이 서버에 등록 코드를 제출하고 사용자 로그인과
새 장치 키 생성이 완료된 뒤에만 서버가 그 장치에 VPN 및 파일 서버 정책을 발급한다.
패키지 유출, 링크 재사용 또는 다른 사용자의 설치만으로 내부망 접근 권한이 생겨서는 안 된다.

## 5. 핵심 사용자 여정

1. 관리자가 서버 설치를 완료하고 VPN, 파일 서버 엔드포인트와 접근 정책을 등록한다.
2. 관리자가 VPN·파일 공유·사용자 범위를 선택한 클라이언트 배포 프로필을 게시한다.
3. 허가된 사용자가 로그인한 웹 포털에서 자신에게 배정된 Windows 프로그램을 내려받는다.
4. 사용자가 설치한 G-One Windows 프로그램에서 로그인하고 장치를 등록한다.
5. 서버가 사용자·장치·등록 코드 상태를 검증하여 짧은 세션과 장치 정책을 발급한다.
6. Windows 서비스가 WireGuard 터널을 연결하고 허용된 내부망 CIDR만 라우팅한다.
7. 클라이언트가 서버에서 허용한 SMB 공유만 연결한다.
8. 계정·장치·정책이 회수되거나 세션이 끝나면 VPN과 공유 연결을 정리한다.
9. 지원 담당자가 티켓에 연결된 지원을 요청하면 사용자가 권한별로 명시적으로 동의한다.
10. 패키지 생성·다운로드, 등록, 요청, 결정, 연결, 종료 및 실패를 감사 기록에 남긴다.

## 6. 기본 보안 정책

- 기본 거부와 최소 권한을 적용한다.
- VPN의 `AllowedIPs`만 신뢰하지 않고 Debian의 전달 방화벽에서 장치별 목적지 CIDR과
  포트를 강제한다.
- 사용자 인증과 장치 인증을 분리하며, 계정 로그인만으로 새 장치를 무조건 신뢰하지
  않는다.
- 브라우저 관리자 영역은 별도 경로와 API 권한을 사용하고 관리자 고위험 작업에는
  재인증 또는 MFA를 적용할 수 있어야 한다.
- VPN 키와 장치 키는 장치별로 발급·회전·폐기하며 서버 비밀은 파일 권한 또는 전용
  비밀 저장 경계로 보호한다.
- 파일 서버 자체 ACL을 최종 권한 경계로 유지한다. G-One의 네트워크 허용은 파일 서버
  인증·인가를 대체하지 않는다.
- 원격 지원은 만료되는 티켓, 명시적 사용자 동의, 권한별 승인과 즉시 종료를 요구한다.
- 감사 이벤트는 일반 애플리케이션 로그와 분리하고 비밀을 기록하지 않는다.

## 7. MVP 포함 범위

- 단일 조직, 단일 G-One Debian 서버, 단일 WireGuard 인터페이스
- 내장 관리자·사용자 인증과 향후 OIDC/AD·LDAP 어댑터 계약
- Windows 장치 등록, VPN 연결·회수와 상태 표시
- 관리자 정의 배포 프로필과 인증된 웹 기반 Windows 설치 파일 다운로드
- 하나 이상의 별도 SMB 파일 서버 및 공유 정책
- 티켓 생성, 지원 요청, 동의·거절·만료·종료
- 관리자 웹과 사용자 웹의 명시적 권한 경계
- 감사 조회, 백업·복구, 업데이트 및 진단 절차

## 8. MVP 제외 범위

- 고가용성 서버 군집 및 다중 VPN 게이트웨이
- NFS 클라이언트를 Windows MVP의 주 경로로 사용하는 기능
- G-One 웹 서버가 파일 내용을 저장하거나 전달하는 기능
- 동의 없는 원격 제어, 백그라운드 감시 또는 숨겨진 세션
- 공개·익명 Windows 설치 패키지 다운로드 및 비밀이 내장된 사용자별 실행 파일
- Active Directory 도메인 컨트롤러 자체 구현
- 파일 서버 ACL을 G-One 데이터베이스만으로 대체하는 기능

## 9. 다음 단계 전에 필요한 승인

이 기준선과 `TARGET_ARCHITECTURE.md`를 검토한 후 다음을 확정해야 한다.

1. 지원할 Windows 최소 버전과 CPU 아키텍처
2. 예상 사용자/장치 수와 내부망/파일 서버 CIDR 구조
3. 초기 파일 서버 종류와 인증 방식(AD, 로컬 SMB 계정 등)
4. 원격 지원의 필수 기능(화면 보기, 입력, 파일 전송, 클립보드)과 기술 검증 범위
5. 내장 계정의 MFA 요구 여부 및 첫 AD/OIDC 연동 우선순위
6. 로그 보존 기간, 백업 RPO/RTO 및 접근 회수 목표 시간
7. 기존 소스 교체 및 새 디렉터리 골격 구현 착수 승인
