# Project G-One 제품 및 아키텍처 방향

## 1. 문서 목적과 상태

이 문서는 Project G-One의 제품 범위, 보안 원칙, 구성 요소와 단계별 구현 기준을
정의하는 단일 기준점이다. 구현 세부사항은 검증 과정에서 바뀔 수 있지만, 변경 시에는
보안 경계와 사용자 영향을 함께 기록한다.

- 상태: `요구사항 기준선`
- 최초 작성일: `2026-09-09`
- 대상: 제품 관리자, 중앙 관리자, 클라이언트 사용자, 개발·운영 담당자
- 다음 검토 시점: MVP 위협 모델 및 배포 토폴로지 검토 완료 후

## 2. 핵심 정의

> Project G-One은 불특정 다수의 사용자를 대상으로, 중앙 관리자가 제로 트러스트
> 원칙에 따라 WireGuard 사설망, 파일 서비스와 원격 지원을 하나의 Python 기반 웹
> 관리 환경에서 안전하고 간편하게 운영하도록 돕는 통합 관리 플랫폼이다.

### 해결하려는 문제

- VPN, 파일 서버, 계정, 원격 지원 도구가 분리되어 사용자 등록과 회수가 반복된다.
- 관리자가 현재 접속 상태와 사용자 간 통신 경로를 한눈에 파악하고 제어하기 어렵다.
- 원격 지원을 빠르게 시작하면서도 피지원자의 명시적 동의를 보장하기 어렵다.
- Proxmox, Vaultwarden 같은 별도 운영 서비스를 한 관리 흐름에서 다루기 어렵다.

### 사용자와 가치

| 사용자 | 필요한 결과 | 제공 가치 |
| --- | --- | --- |
| 중앙 관리자 | 사용자·장치·정책·서비스를 한곳에서 관리 | 반복 작업 감소, 최소 권한 정책, 감사 가능성 |
| 일반 사용자 | SSO로 허가된 내부 파일 서비스에 접속 | 단순한 온보딩과 일관된 접근 경험 |
| 원격 지원 담당자 | 온라인 사용자를 골라 즉시 지원 요청 | VPN 내부 경로와 동의 기반 세션 시작 |
| 피지원자 | 지원 요청의 주체와 목적을 확인하고 결정 | 명시적 수락·거절 및 세션 가시성 |

## 3. 제품 원칙

1. **신뢰하지 않고 검증한다:** 사용자, 장치, 세션과 서비스 요청을 각각 인증·인가한다.
2. **기본 거부와 최소 권한:** 사용자 간 연결 및 서비스 접근은 정책으로 허용된 경로만 연다.
3. **동의 없는 원격 제어 금지:** 긴급 우회 기능을 기본 제공하지 않고 모든 지원 세션을 감사한다.
4. **프로토콜 중립성:** SMB를 우선 지원하되 NFS, WebDAV 및 이후 프로토콜을 플러그인처럼 확장한다.
5. **제어면과 데이터면 분리:** 웹 관리 서비스 장애가 기존 VPN·파일 데이터 전송을 불필요하게 중단하지 않게 한다.
6. **비밀 최소화:** 비밀번호와 장기 키를 평문 저장·기록하지 않고 회전과 폐기를 지원한다.
7. **단계적 통합:** 외부 제품은 API 어댑터로 연결하고 장애나 권한이 핵심 서비스로 전파되지 않게 한다.
8. **로그인은 매번 명시적으로:** Windows 자격 증명 저장과 자동 로그인을 금지하고 짧은 앱 세션을 사용한다.
9. **로그인 이후는 자동으로:** 인증 후 VPN과 허가된 SMB 공유 구성은 에이전트가 자동 수행한다.
10. **조직 경계 우선:** 서비스형 멀티테넌시의 신원·정책·네트워크·데이터·감사를 조직별로 격리한다.

## 4. 기능 범위

### 4.1 통합 신원과 권한

- OpenID Connect(OIDC)를 우선 SSO 표준으로 사용하고, 필요한 경우 SAML 또는 LDAP 연결을
  별도 어댑터로 제공한다.
- Authentik을 우선 IdP 연동 대상으로 검증하고 Synology 계정 체계는 지원 가능한 공식
  인터페이스와 배포 모델을 확인한 뒤 어댑터 범위를 확정한다.
- VPN 키는 계정 그 자체가 아니라 사용자에게 등록된 **장치 자격 증명**으로 취급한다.
  계정 비활성화, 그룹 변경 또는 장치 폐기 시 해당 피어 정책과 키를 회수한다.
- 관리자, 지원 담당자, 감사자, 일반 사용자를 구분하는 역할 기반 접근 제어(RBAC)를
  제공하며 고위험 작업에는 재인증과 선택적 다중 인증을 요구한다.

### 4.2 WireGuard VPN 관리

- 사용자·장치별 피어 등록, 키 교체·폐기, 구성 배포와 접속 상태 조회를 지원한다.
- 중앙 정책으로 피어 간 연결, 서비스 대역 접근, DNS와 라우트를 관리한다.
- `AllowedIPs`만을 보안 경계로 간주하지 않고 방화벽 규칙과 정책 엔진을 함께 적용한다.
- 접속 상태는 WireGuard 핸드셰이크 등 관측값을 기반으로 `온라인`, `최근 접속`,
  `오프라인`, `알 수 없음`으로 표현하며 이를 절대적인 사용자 활동 증명으로 오인하지 않는다.

### 4.3 파일 서비스 관리

- 1차 프로토콜은 SMB이며 공유 생성, 사용자·그룹 매핑, 접근 정책과 연결 안내를 관리한다.
- NFS와 WebDAV를 후속 어댑터로 추가할 수 있도록 공통 `서비스`, `공유`, `주체`, `권한`,
  `엔드포인트` 모델을 사용한다.
- 실제 파일 데이터는 브라우저 관리 서버를 경유시키지 않고 VPN 데이터면에서 전송한다.
- 프로토콜별 인증 의미가 다르므로 SSO 토큰을 SMB/NFS 자격 증명으로 직접 재사용하지 않는다.
  짧은 수명의 자격 증명, 디렉터리 연동 또는 플랫폼별 브로커 방식은 위협 모델 후 결정한다.

### 4.4 동의 기반 원격 지원

1. 관리자는 웹 콘솔의 접속 장치 목록에서 지원 대상을 선택하고 목적을 입력한다.
2. 서버는 대상 장치에 만료 시간이 짧은 지원 요청을 전달한다.
3. 피지원자는 요청자, 목적, 요청 권한과 만료 시간을 확인해 수락하거나 거절한다.
4. 수락 시 서버는 해당 두 장치와 필요한 포트에만 제한된 일회성 세션 권한을 발급한다.
5. 세션 중 양쪽에 지원 상태를 표시하고 어느 쪽이든 즉시 종료할 수 있게 한다.
6. 요청, 수락·거절, 시작·종료, 참여자, 부여 권한과 정책 변경을 감사 로그에 남긴다.

화면 보기, 입력 제어, 파일 전송, 클립보드는 각각 별도 권한으로 동의받는다. 원격 지원
프로토콜과 클라이언트 구현은 MVP 기술 검증에서 결정하며, 웹 콘솔은 세션 승인과 연결
조정만 담당하고 미디어·화면 데이터의 종단 간 보호를 우선한다.

### 4.5 외부 서버 통합

- Proxmox와 Vaultwarden을 초기 통합 후보로 두되 공식 API 범위, 최소 권한 계정,
  버전 호환성 및 감사 이벤트를 먼저 확인한다.
- 통합별 자격 증명은 암호화 저장하고 읽기 전용 상태 조회부터 시작한다.
- 공통 어댑터 계약은 상태 확인, 리소스 링크, 제한된 작업, 권한 검사, 오류 격리와
  감사 이벤트를 포함한다.
- 외부 서비스의 관리자 화면을 무조건 임베드하지 않고, 동일 출처 정책과 클릭재킹,
  SSO 세션 격리 위험을 검토해 링크 또는 API 기반 기능을 선택한다.

## 5. 논리 아키텍처

```text
관리자/사용자 브라우저
        │ HTTPS + SSO
        ▼
Python 관리 웹/API ─── 정책 엔진 ─── 감사 이벤트 저장소
        │                 │
        ├── WireGuard 제어 어댑터 ── VPN 게이트웨이/방화벽
        ├── 파일 서비스 어댑터 ───── SMB (우선), NFS, WebDAV
        ├── 지원 세션 조정기 ─────── 사용자 장치 에이전트
        └── 외부 통합 어댑터 ─────── Proxmox, Vaultwarden, 기타 서버

IdP (Authentik / Synology 연동 후보) ── OIDC/SAML/LDAP ── 관리 웹/API
```

Python 웹/API는 정책과 수명 주기를 관리하는 제어면이다. WireGuard 터널, 파일 전송 및
원격 화면 스트림은 데이터면으로 분리한다. 초기 구현 후보는 ASGI 기반 API, 작업 큐,
관계형 데이터베이스와 OS별 경량 장치 에이전트이나, 구체 제품과 프레임워크는 기술 검증
및 위협 모델 이후 ADR로 확정한다.

### 핵심 도메인 모델

- `Identity`, `Group`, `Role`: 외부 신원과 내부 권한
- `Device`, `VpnPeer`, `ConnectionState`: 장치 자격 증명과 관측 상태
- `Policy`, `NetworkGrant`, `ServiceGrant`: 피어·서비스 접근 결정
- `FileService`, `Share`, `ProtocolAdapter`: 프로토콜 중립 파일 서비스
- `SupportRequest`, `Consent`, `SupportSession`: 원격 지원 승인과 수명 주기
- `Integration`, `ExternalResource`: 외부 서버 연결
- `AuditEvent`: 행위자, 대상, 결과, 시각, 상관관계 ID를 가진 변경 불가 이벤트

## 6. 보안 및 운영 요구사항

- 관리 API와 에이전트 통신은 TLS를 사용하며 에이전트는 상호 인증한다.
- CSRF, SSRF, 세션 고정, 권한 상승, 명령 주입과 공급망 공격을 위협 모델에 포함한다.
- 구성 변경은 검증, 원자적 적용, 상태 확인과 이전 구성으로의 롤백 절차를 갖는다.
- 감사 로그는 애플리케이션 로그와 분리하고 민감 정보 마스킹, 보존 기간, 내보내기와
  무결성 검증을 지원한다.
- 연결 상태, 정책 배포 실패, 인증 실패, 키 만료와 외부 통합 장애를 관측하고 경고한다.
- 백업에는 정책·메타데이터·암호화된 비밀을 포함하고 복구 훈련 및 키 분실 절차를 문서화한다.
- 개인정보 최소 수집, 보존·삭제 정책, 사용자 통지 및 운영 지역의 법적 요구를 배포 전에 검토한다.

## 7. MVP 범위와 완료 기준

### 포함

1. Authentik OIDC 로그인과 기본 RBAC
2. 단일 WireGuard 게이트웨이의 장치 등록·폐기 및 정책 기반 서비스 접근
3. 접속 장치 상태 목록과 상태 근거/갱신 시각 표시
4. 단일 SMB 서버의 공유 목록 및 그룹 기반 접근 구성
5. 한 종류의 데스크톱 환경에서 동의 기반 원격 지원 요청·수락·종료
6. 보안 관련 관리 작업과 지원 세션의 감사 로그
7. Proxmox 읽기 전용 상태 카드 한 개로 외부 통합 계약 검증

### 후속 범위

- 다중 VPN 게이트웨이, 고가용성, 사이트 간 연결과 자동 장애 조치
- NFS·WebDAV 실제 프로비저닝 및 다중 파일 서버
- Synology별 계정·파일 서비스 어댑터의 제품화
- Vaultwarden 관리 작업과 외부 서비스 쓰기 작업
- 다중 원격 지원 프로토콜, 모바일 지원, 녹화

후속 범위는 금지 항목이 아니다. SMB 우선 MVP가 다른 프로토콜과 통합을 막지 않도록
도메인 및 어댑터 경계를 먼저 검증한다.

### 완료 기준

- 신규 사용자가 SSO 후 장치를 등록하고 허가된 SMB 공유에 접근할 수 있다.
- 허가되지 않은 피어·서비스 경로가 네트워크 테스트에서 차단된다.
- 관리자는 상태의 최신성을 확인하고 온라인 장치에 지원을 요청할 수 있다.
- 거절·만료된 요청으로 세션을 열 수 없으며, 수락한 권한 외 기능은 사용할 수 없다.
- 계정 또는 장치 폐기 후 정한 시간 내 VPN과 서비스 접근이 회수된다.
- 모든 고위험 작업이 행위자와 결과를 포함한 감사 이벤트로 조회된다.

목표 시간, 동시 사용자 수, 가용성, 복구 목표(RTO/RPO)와 로그 보존 기간은 배포 규모와
법적 요구를 확인한 뒤 수치화한다.

## 8. 단계별 로드맵

### 0단계 — 위험 검증

- [ ] 배포 대상 OS, 네트워크 토폴로지, 예상 사용자·장치 수 조사
- [ ] 신원 연동 및 계정 폐기 흐름 검증
- [ ] STRIDE 기반 위협 모델과 데이터 흐름도 작성
- [ ] 원격 지원 기술의 동의 UX, NAT, 암호화와 라이선스 검증

### 1단계 — 제어면 기반

- [ ] Python API, 데이터 모델, OIDC, RBAC와 감사 로그 구축
- [ ] WireGuard·방화벽 어댑터 및 구성 롤백 구현
- [ ] 사용자·장치 온보딩과 상태 화면 구현

### 2단계 — 핵심 사용자 여정

- [ ] SMB 어댑터와 서비스 접근 정책 구현
- [ ] 장치 에이전트 및 원격 지원 승인 흐름 구현
- [ ] 종단 간 권한 회수, 거절, 만료와 장애 시나리오 시험

### 3단계 — 운영 및 확장
