# Project G-One MVP 위협 모델

## 목적과 경계

이 문서는 제품 방향의 **기본 거부, 조직 격리, 명시적 동의, 제어면/데이터면 분리**를
구현과 출시 검토에서 확인할 수 있는 위협 기준으로 바꾼다. MVP의 보호 대상은 신원·역할,
장치 자격 증명, WireGuard 키와 정책, 파일 접근 권한, 지원 동의, 통합 비밀 및 감사
이벤트다. 파일 내용과 원격 화면 스트림은 제어면을 통과하지 않는다.

```text
[브라우저] -- HTTPS/OIDC --> [G-One 제어면] -- SQL/TLS --> [메타데이터 DB]
                                  | mTLS/작업 서명
             +--------------------+---------------------+
             |                    |                     |
       [Windows 에이전트]   [VPN/방화벽 어댑터]   [서비스 어댑터]
             |                    |                     |
       사용자 동의 UI       WireGuard 데이터면      SMB/Proxmox
```

### 신뢰 경계

1. 인터넷과 HTTPS 리버스 프록시 사이
2. 프록시와 제어면 사이(신뢰 프록시 주소를 명시적으로 제한)
3. 조직별 API 객체와 데이터베이스 행 사이
4. 제어면과 장치 에이전트·인프라 어댑터 사이
5. 지원 요청 승인 제어와 실제 원격 화면 데이터 사이

## STRIDE 위험과 필수 통제

| 위협 | 대표 시나리오 | MVP 필수 통제 | 검증 증거 |
| --- | --- | --- | --- |
| 위장 | 탈취한 세션 또는 에이전트 키로 접속 | OIDC issuer/audience/nonce 검증, 짧은 세션, 에이전트 mTLS, 키 회전·폐기 | 만료·오발급자·폐기 키 거부 시험 |
| 변조 | WireGuard/방화벽 구성을 중간에 바꿈 | 서명된 작업, 사전 검증, 원자적 적용, 적용 후 확인과 롤백 | 실패 주입 및 이전 정책 복구 시험 |
| 부인 | 관리자가 정책 변경 또는 지원 시작을 부인 | 업무 변경과 같은 트랜잭션의 append-only 감사, 상관관계 ID, 외부 보관 | 행위자·결과·요청 ID 조회 시험 |
| 정보 노출 | 조직 간 객체, 토큰, 파일 경로 또는 화면 유출 | 모든 조회의 서버측 tenant 조건, 로그 마스킹, 비밀 암호화, 데이터면 분리 | 교차 tenant API/DB 시험과 로그 검사 |
| 서비스 거부 | 로그인·지원 요청·상태 보고 폭주 | 주체/IP별 제한, 짧은 timeout, bounded queue, 어댑터 회로 차단 | 부하 시험과 외부 통합 장애 시험 |
| 권한 상승 | 일반 사용자가 관리자 API 또는 미동의 제어 기능 사용 | 중앙 RBAC/정책 결정, 객체 소유권 검사, 권한별 동의, 일회성 grant | 역할 매트릭스와 거절·만료·재사용 시험 |

## 출시 차단 조건

다음 항목이 하나라도 남으면 인터넷에 연결되는 운영 배포를 허용하지 않는다.

- 개발용 공유 HS256 콘솔 로그인을 Authentik OIDC/JWKS 검증으로 교체하지 않음
- 에이전트 상호 인증, 장치 등록 승인 및 자격 증명 폐기 흐름이 없음
- tenant 격리 자동 시험 또는 데이터베이스 마이그레이션/복구 시험이 실패함
- 지원 요청의 소유자 확인, 만료, 권한별 동의 또는 양측 종료가 우회됨
- 방화벽 기본 거부와 허가된 서비스 경로 시험이 통과하지 않음
- 감사 로그 무결성·보존·내보내기와 비밀 마스킹 기준이 정해지지 않음
- 백업 복원 훈련 없이 스키마 또는 정책 변경을 배포함

## 검증 책임과 갱신

보안 담당자는 위협과 잔여 위험을 승인하고, 제품 담당자는 동의 UX와 개인정보 보존을
승인하며, 운영 담당자는 네트워크·복구 증거를 보관한다. 신뢰 경계, 인증 방식, 원격 지원
프로토콜 또는 외부 통합의 쓰기 권한이 바뀔 때 이 문서를 같은 변경에서 갱신한다.
